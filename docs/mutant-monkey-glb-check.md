## 2. 軽量化の試作（未確定）
三角形は meshoptimizer で1回だけ減らした（UV の継ぎ目は保たれる）。

- 6,000 三角形以下は**できる**。
- 減らした後、頂点1つでだけつながった小さな破片が 72 できる（毛先・前腕のとげ。見た目には出ない）。本加工で、とげを残すか消すかを決めて整える。

## 3. 修正方針（案）
1. **向きと原点**：前を +Z、足の裏を y=0 にする。大きさは通常の猿（高さ 1.56）の 1.2倍（高さ 1.87、主人公 2.05）で並べた画像を作った（**暫定**）。
2. **小さな三角形1枚**を消す。
3. **尾**：骨を3つ入れ、休みの形でも後ろ下がり（水平から30〜40°下）に持ち上げる。板状の薄い向きを少しふくらませて（左右に1.6倍ほど）丸みを出す。形はスクリプトで直せる（作り直し不要）。
4. **手の指先が埋まる件**：腕の骨の休みの角度を少し上げる（または歩きの動きで手が地面に触れる高さに合わせる）。
5. **生殖器**：ゲームでは目立たないよう、股の形をならして消すのがおすすめ（**ユーザー確認**）。
6. **三角形とテクスチャ**：案A。

## 4. 実装の方針
- 本編に GLB を読む仕組みを足すより、猪・ヌシと同じく、**ゲーム用の小さな形式**（位置・法線・UV・骨の重み・三角形を詰めたもの＋色テクスチャ JPEG）に変換する。
- 別ファイル（`data/models/mutant-monkey.js` の予定）にして、出番の前だけ読み込む。
- 動きは、猪・ヌシと同じく GPU で骨を動かし、**動きはコードで作る**（決まった動きのデータは持たない）。

骨（約19本）：腰・背・胸・首・頭、左右の 肩〜上腕・前腕・手、左右の 太もも・すね・足、尾3。
- 重みは、骨からの距離で付けてから、面のつながりに沿ってならす。
- 尾は脚と、左右の手足は互いに、まざらないよう分けて付ける。
- 確認用に動きの画像を作り、ユーザーの承認を得る。

### 既存の敵 AI の流用
| 必要な動き | 流用できる所 |
|---|---|
| 待機・歩く | 通常の敵の待機・うろつき・気づく（共通の処理） |
| 四つ足で走る | 追いかけ（共通）。足の運びは新しく作る |
| 飛びかかり | 通常の猿の「ため（wind）→突進（dash）」 |
| ひっかき | 熊の「ため→振りかぶり（strike）」の型（近い距離で前腕を振る） |
| ひるみ | 共通の怯み値（POISE）・のけぞり・押し返し |
| 倒れる | 共通の倒れる処理（倒れた後の扱いは決める必要あり） |

新しく作るもの：
- スズキを追う（主人公以外を狙う）
- イベントでの出現と終わり
- 新しい種類 `mutant` の動き（骨の回し方）
- 強さ（体力・攻撃力・速さ。**暫定**値から）

既存の通常の猿（`makeMonkey`）と双子猿ボスには手を入れない。

## 5. 推奨手順
1. 確認事項（6節）の答えをもらう。
2. 加工：向き・原点・大きさ・破片・尾・股・三角形・テクスチャ → 加工後の GLB（`assets/models/mutant-monkey/game/`）とゲーム用データを作り、台帳に版を記録。
3. 骨と重み → 曲げた姿勢の確認画像（承認）。
4. 7つの動き（待機・歩く・四つ足で走る・飛びかかり・ひっかき・ひるみ・倒れる）→ 動きの確認画像（承認）。
5. AI（`mutant`）と暫定の強さ → 試遊用に山王で1体出せるようにする。
6. 作業F（スズキ初登場）に組み込む（スズキの見た目・台詞の承認後）。
7. テスト（読み込み・捨てる・重さ）と文書。

## 6. 仮実装で進められる範囲
加工前の元モデルのままでも、次は先に進められる。仮のまま正式扱いにはしない。
- 骨・重み・7つの動き
- AI・当たり判定・体力
- 出現の仕組み

尾と股の形を直すと、重みを付け直す必要がある。そのため 2.（加工）を先に決めるのが手戻りが少ない。

## 7. 確認したいこと
1. 生殖器：股の形をならして消してよいか（おすすめ）。
2. 尾：後ろ下がりに持ち上げ、少し丸くする（おすすめ）か。ニホンザルらしく短くするか。このままか。
3. 大きさ：通常の猿の 1.2倍（主人公より少し低い）でよいか。
4. 軽量化：案A（5,793 三角形、色 1024）でよいか。鱗の凹凸を残すなら法線マップも付ける。
5. 「撃退」は倒す（倒れる動き）か、逃げ去るか（その後の再登場の有無）。
6. 見た目：通常の猿（デフォルメ）と比べて写実寄りで、並ぶと画風が違う。「異質に見せる」意図どおりでよいか。
