**house110 は、標準型の売場を第一候補にし、1階と2階を合わせて輪郭込み15,000三角形未満、表示中の1階層を10,000三角形・通常描画50 calls以内とする案を推薦します。** 商品は固定棚とまとめて描き、中央棚は商品込みでまず1.2 m以下に抑えます。性能と操作性の両方で条件が厳しいのは、スズキ同行中、仰角+35°で棚を手前に置き、階段や出口を操作する場面です。

## 2. 階と棚をどう描くか

**2階は本部と同じ別平面への暗転移動を使い、商店では各階を生成時から別の `Group` にします。** 各グループに床・腰壁・家具の本体と輪郭、上壁、引き戸、光、操作の印を収めます。暗転中に現在階を切り替えれば、非表示階の通常描画は0 callsになります。両階の形状はメモリに残ります。親の `visible` だけでは当たり・操作・戸の更新は止まらないため、それらも現在階に限定し、移動先の当たりを有効にしてから主人公と同行スズキを置きます。本部の `p3bFloor()` は本部座標を直接参照するので、商店用の原点と移動先を渡せる形が必要です。根拠は `index.html:10933` `p3bFloor()`、`index.html:12135` `P3B_PLAN`、`index.html:12395` `p3aInteriorBuild()`、`index.html:12438` `p3bInteriorTick()` です。

| 手法 | 効果の見積もりと採用方針 |
|---|---|
| 固定棚と商品を `GB` で結合 | 棚8箱＋商品30箱を六面メッシュと輪郭で個別に描くと約76 calls・912三角形。底なし `GB` に棚単位でまとめると約2 calls・760三角形。同じ階の既存 `GB` に入れれば追加0 calls。**常時表示の低い棚は階に結合し、個別に隠す必要のある高い棚だけ分離**するのが扱いやすい。`index.html:1259` `GB.box()`、`index.html:12395` `p3aInteriorBuild()` |
| `InstancedMesh` | r128の本編に実例あり。棚を `GB`、同形商品30個をインスタンス化し、それぞれに輪郭を付けると約4 calls。六面商品なら計880三角形。色違い・寸法違いをまとめられる。固定商品の初版は既存 `GB` が簡潔で、商品群を独立して表示・差し替えたい場合にインスタンス化が候補。`index.html:1236` `inkInst()`、`index.html:4666` `setColorAt()` 使用箇所 |
| 材質・光の共有 | 食品・生活用品・農業用品は箱の比率、頂点色、並び方で区別できる。材質だけ共有しても別メッシュの calls 削減は0。窓光は同じ濃さ・同じ階の面を結合すれば、同時に見える光が *n* 枚なら通常 *n* → 1 call。半透明面の重なりによる画素負荷は残る。`index.html:12304` `p3inLightMesh()`・`p3inWindowLights()` |
| 輪郭 | `inkGeo()` は本体と同数の三角形を追加する。棚の支柱・外形には残し、小箱が密集して黒く潰れる場合は商品だけ輪郭を省く案。底なし商品30個なら1棚あたり300三角形減。独立した輪郭なし商品バッチを足す場合は、その本体の1 callも数える。`index.html:1230` `inkGeo()`、`index.html:12395` `p3aInteriorBuild()` |
| 視界の外 | 視錐台から丸ごと外れた棚バッチなら本体・輪郭の最大約2 callsを省ける。階全体を結合すると一部が映る限り全体が描画対象。逆に、壁の裏でも視錐台内にある棚は自動では消えない。小さい店ではまず階別表示を使い、棚別分割は遮蔽対策か実測上の効果がある場所に限る。`index.html:12395` `p3aInteriorBuild()`、`index.html:12438` `p3bInteriorTick()` |

## 3. 棚の高さ、標準／軽量、iPhone操作

屋内仰角はPC・iPhone共通で+35～+80°、既定は約47.6°です。カメラは主人公の高さ1.3 mを基準に回り、肩方向へ0.6 mずれます。通常の棚には、手前の壁上部を消す `p3bInteriorTick()` の処理が効きません。根拠は `index.html:951` `CAM`、`index.html:10046` `CAM_PITCH`、`index.html:10165` `updateCamera()`、`index.html:12438` `p3bInteriorTick()` です。

**遮蔽の見積もり**として、肩ずれを省いた側面図で、見たい点の高さを *h*、そこからカメラ側の棚の縁までの水平距離を *d* とすると、視線高の一次近似は *h + d × tan(仰角)* です。高さ1.3 mの基準点を狙い、棚の縁まで0.5 mなら、視線高は+35°で約1.65 m、既定で約1.85 m、+80°で約4.14 m。**1.8 m棚は最低角で主人公の上体を隠し得ます。** また、床の散乱物を見る場合、+35°で1.2 m棚の直後は約1.7 m先まで床が隠れる見積もりです。後者は床を通る平行視線での概算で、実画面の遮蔽距離は視点・肩ずれ・向きで変わります。

- **棚配置の推薦案**は、中央棚を商品込み1.0～1.2 m、高棚を1.6～1.8 mの壁寄せ候補とし、入口・階段の正面を低く空ける形です。散乱物は棚の真裏に集中させず、通路端からも見える位置に置きます。壁寄せ棚もカメラを反転すると手前に来るため、両側から確認します。より密な売場を好む場合は、高棚の上段と商品を一緒に隠せる別バッチにする案があります。
- **標準／軽量**は現行では町と森林の細かさを変え、屋内家具の数は同じです。初版は両設定で同じ棚構成を推薦します。iPhoneで軽量を選ぶだけでは棚の calls は減りません。実機で超過した場合の候補は、商品輪郭と窓光の重なりを減らすことです。端末判定による画素比上限は `LOWQ` で1.5、通常1.75。影は別設定なので比較時に固定します。`index.html:931` レンダラー初期化、`index.html:12493` `gfxRad()`、`index.html:12818` `applyDetail()`、`index.html:15476` `applyShadow()`
- **画面上の重なり**は端末で異なります。PCでは行動案内 `#prompt` が下中央、目的の帯 `#objective` が上中央、ミニマップ `#mini` が右側です。iPhoneのタッチモードでは**ミニマップは非表示**で、確認対象は地図ボタンです。横持ち・低い画面では行動ボタンが右下54×54 CSS px、行動案内が下端から160 px＋安全領域に来るため、案内が出た瞬間に主人公や戸口が隠れないかを見ます。縦持ちは別のCSSで案内がさらに上がる場合があります。入口文の候補は短い「よろず屋に入る」、地図なし時は「入口を確かめる」→「入る手がかりがない」。表示を出さない案もあり、推薦は入口を発見できる短文案です。`index.html:109`・`:141`・`:167`・`:357`・`:379`・`:382`・`:493`～`:507` HUDのCSS、`index.html:10955` `p3bOutside()`
- **スズキ同行**では人物描画に加え、配置時に候補地点の当たりと見通しを調べます。商品には個別の当たりを置かず、棚1台に箱当たり1個を基本とします。入口・踊り場には主人公の背後だけでなく斜めにも同行者を置ける余白を確保します。追加 calls・フレーム時間は**不明**。屋外で「指示する」が店の入口に勝つ競合は、現行の農家限定例外では解消されません。`index.html:8919` `interactables()`、`index.html:12443` `p3aEnter()`、`index.html:13679` `szPlaceBehind()`

## 4. 間取り3型の比較

同じ数量・同じ階単位の `GB` なら、間取りを変えても固定物の三角形数・calls はほぼ同じです。以下は棚配置による**見やすさと描画傾向の推測**です。`index.html:12395` `p3aInteriorBuild()`、`index.html:12438` `p3bInteriorTick()`。

| 型 | 描画傾向 | 見やすさ・操作 |
|---|---|---|
| **標準型（推薦）** | 中央の低棚を階に結合しやすい。壁際の高棚だけ分離できる | 入口からレジを見せ、裏倉庫と階段への曲がり口を空けやすい。約14×13 mの外形になじむ |
| 細長い型 | 通路の長手方向で棚列が同時に映りやすく、棚別カリングの利益は小さめ | 進行方向は読みやすい。横向き視点では手前の連続棚が主人公を隠しやすく、行き止まりでスズキと折り返す余白が要る |
| 回遊型 | 島棚を個別に隠す設計ではバッチが増える。低棚を結合できれば標準型と同水準 | 同行者を避けて回れる一方、角を曲がるたびに手前の棚が変わる。入口から階段への見通しと、四隅での右スワイプを要確認 |
