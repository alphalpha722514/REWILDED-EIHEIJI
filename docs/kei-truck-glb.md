## 4. フロントガラス（修理後）

**原因**：修理後の元の GLB には、フロントガラスの面そのものが無い（窓枠だけ）。描き方（材質）の問題ではない。

- 調べ方：前から光線を当て、窓枠の内側（幅 ±0.15・高さ 0.40〜0.50、元の単位）で当たる所を測った。
  - 修理前：341本すべてがガラスの面（z 0.28〜0.35、上ほど後ろへ傾く）に当たる＝ひびの入ったガラスは形として存在する。
  - 修理後：341本のうち 109本は何にも当たらず車の中を抜け、残りは運転席の奥（z 0.02〜0.08）に当たる＝ガラスの面が無い。
  - 材質は1つで、透明（アルファ）の設定は無い。絵の中にもガラスの部分は無い。
- 直し方（ゲーム用のコピーだけ）：窓枠の内側に**曲面のガラス**（縦6×横12 の格子、144 三角形、前から見て少し丸い・上ほど後ろへ傾く）を足した。別の材質（`kei_truck_glass`、薄い青緑・不透明度 0.32・両面）。ゲームでは光沢のある半透明（`MeshPhongMaterial`、影は落とさない）で描く。
- 修理前のひびの入ったガラスは元の形のまま（何も足していない）。
- 横の窓も修理後は開いている（ガラスが無い）。**今回は足していない**（「フロントガラス以外の採用済みデザインを変更しない」ため）。足すなら同じやり方でできる（§12 の確認事項）。

## 5. 車輪・ドア・あおりの分離

- **車輪4つ：分けた。** 元は1つのつながった形なので、タイヤ（ホイールを含む）の円柱の中（半径＋0.006、内側と外側の幅＋0.004〜0.008、元の単位）に3つの頂点がすべて入る三角形を車輪の形へ移した。車輪の形の原点は車軸の中心（名前 `wheel_fr`・`wheel_fl`・`wheel_rr`・`wheel_rl`＝右前・左前・右後ろ・左後ろ）。
  - 確かめたこと（全長 3.75m のとき。そのあと大きさだけ変えたので形は同じ）：車体だけ・車輪だけを並べて描き、車体にタイヤの切れ端が残っていない・車輪に車体（泥よけ・車台）が付いて来ていないことを見た。車輪を60°回し前を切った姿でも、穴や浮いた三角形が見えない（`python3 tools/kei-truck-studio.py 出力.png both parts|spin`）。
  - 車輪の半径：修理前 0.427m（前）・0.423m（後ろ）、修理後 0.418m・0.415m。
- **ドア2枚・荷台のあおり：今回は分けていない（段階実装）。** 理由：
  - ドアとあおりは車体と同じ1つのつながった形で、境目に切れ目（別の島）が無い。円柱のように単純な形でもないので、三角形で切ると縁がギザギザになり、開けたときに車体側に穴が開く（中の形が無い）。
  - 開け閉めは今の仕様（乗る・降りる・修理・運転）では要らない。
  - 将来分けるなら、案：(1) Blender で境目を切って穴の内側を埋める（ユーザーの作業。【3Dモデル制作依頼】の形で頼む）、(2) ゲーム用のコピーでドアの板だけを作り直し、元の絵を貼る。どちらも外観の確認が要る。

## 7. ゲームへの組み込み（`index.html`）

- `TRUCK_GLB`・`TRUCK_VIS`・`truckGlbLoad(kind)`・`truckGlbFree()`・`truckGlbDrop(kind)`・`truckVisual(t)`。
- `truckModel()` は位置と向き（ばね）を持つ入れ物（`TRUCK.m`）を作り、中にコードの仮の形（`TRUCK.code`）を入れる。GLB が読めたら入れ物に足し、仮の形を隠す。**読めない・読み終わる前は仮の形のまま遊べる**（さび・パンク・開いたボンネットは仮の形だけ）。
- 見せる形：`trk().repaired` が偽なら修理前、真なら修理後（`truckVisual`、毎コマ `truckUpdate` から）。セーブの値から決めるので、**つづきからでも正しい形**が出る。直したら修理前の形は GPU から外す（`truckGlbDrop('broken')`）。直したあとのセーブでは修理前の形を読まない。
- 先読み：相談のあと（`departureDecision`）部品を集めている間に修理後の形を読んでおき、直した瞬間に切り替える（形が変わる所に土ぼこり）。
- 二重処理の防止：`truckRepair()` は直したあとに呼ばれても何もしない（素材を二度引かない）。`truckFuel()` も同じ。直したことは `truck.repaired` に保存し、偽へ戻す処理は無い。
- 車輪：`TRUCK.wheels` を GLB の車輪に差し替え。回す速さは車輪の半径から。前の2つはハンドルの向きに切れる。車輪はばねの伸び縮みに合わせて上下する（前は浮いたときに下へ伸びるだけで、ねじれた地面では1つの車輪が数cm 沈んだり浮いたりして見えた。大きくしてから目立ったので直した）。
- 素材と GPU：絵は `MeshToonMaterial`（武器の GLB と同じ。絵は線形のまま）、ガラスは半透明の `MeshPhongMaterial`。影を落とす（ガラス以外）・受ける。

変えていないもの：セーブのキー・形、作業F の流れ・台詞・素材の数、運転の操作（PC・iPhone）、地域移動の条件、主人公・NPC・武器・防具・戦闘・防衛戦・スズキ・変異したサル・地形と道路・クラフト。

大きさを変えるとき：`tools/models/kei_truck.json` の `lengthM` を変えて `node tools/models/kei_truck_build.mjs`。そのあと `kei_truck_build.json` の車輪の位置・半径に合わせて `TRUCK_WHEELS`・`wheelbase`・`steerMax`（最小の回る半径）・`gyroP`・`gyroR`・`tireR`・`r`・当たりの箱・`TRUCK_SEAT`・`TRUCK_BED`・調べる距離・降りる場所・見送りの位置・運転中のカメラを同じ倍率で直し、`tests/kei-truck-glb-browser.py` の大きさの範囲も直す。

## 8. 軽量化（指示書の順）

1. **不要な内部形状**：元は1つのつながった形で、中だけにある別の島は無い（調べた）。運転席の中・エンジンの形は外から見えるので残した。
2. **絵の大きさ**：2048 四方×3枚（約3.5MB、GPU では 1枚あたり 約22MB）→ 1024 四方×1枚（約160KB、GPU で 約5.6MB）。金属・粗さ・凹凸の絵はトゥーンの陰影では使わないので外した。
3. **描画の回数**：車体・車輪4つ（＋修理後はガラス）。材質は1つの絵を共有。車輪は回すために分けたので、これ以上はまとめない。修理前と修理後を同時に描くことは無い（隠すか外す）。
4. **三角形**：車体を 55%に（修理前 23,079→14,005、修理後 23,464→15,157。車輪とガラスを含む）。元と並べて、大型バンパーガード・露出したエンジン・大きなマフラー・タイヤの溝・荷台の枠が残っていることを確かめた（`cmp_simplify` の比較画像）。

1. **荷台に積む（容量だけ・初期の段階）**：荷台の中身を `truck.bed`（新しい項目。旧セーブは空）に。車のそばで「荷台に積む／下ろす」。上志比へ車で移ると中身も一緒に移る。`TRUCK_BED` の位置に積んだ物の見た目（木箱など）を置く。
2. **建設に直接使う**：建設・修理の行動で、近く（例 8m）に KEI truck があれば `inv` の次に荷台の中身から引く。
3. **燃料の減り方**（決まったら）：走った距離で減る・携行缶で足す。煩雑にしないため、例：満タンで光明寺⇔上志比を数往復、拠点で補給。
