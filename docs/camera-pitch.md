# 三人称カメラの上下の操作

2026-11-26 正式公開を承認・main へ（v0.90）。cam-pitch の試遊版を iPhone で試遊して問題なし。

ユーザーが承認した A 案。主人公の胸の高さを中心にカメラが上下に回る。上下の操作を加える前の標準構図を、各場面の基準にする。

## 操作

- PC は中ボタンを押しながら上下左右へドラッグする。X で上、Z で下を見られる。C で主人公の背後と、その場面の標準の角度に戻る。
- iPhone は画面右側をなぞる。横で左右、縦で上下、斜めで両方を回せる。左の移動操作と同時に使える。攻撃などのボタン上では各ボタンの操作になる。
- 標準設定では、マウスや指を上に動かすと上を見る。縦のドラッグは横の約 0.6 倍の感度。タッチではなぞり始めの約 10 px の間だけ、横の移動量の 0.35 倍より小さい縦ぶれを抑える。
- 一時停止の「カメラ」で上下の感度を低・標準・高（0.6／1.0／1.5 倍）に切り替えられる。「上下の反転」はマウスとタッチに効く。X と Z の向きは固定。

## 角度と場面

仰角は主人公の胸からカメラを見た角度。小さいほど見上げ、大きいほど見下ろす。範囲は暫定。

| 場面 | 標準 | 見上げの限界 | 見下ろしの限界 |
| --- | ---: | ---: | ---: |
| 屋外 | 約 19° | −10° | +60° |
| 屋内 | 約 48° | +35° | +80° |
| KEI truck 運転中 | 約 19° | +8° | +40° |

場面ごとに従来の仰角との差をラジアンで持つ。屋内、運転中、屋外の順で使う差を選ぶ。入退室・乗降で場面が変わると、その場面の差に戻る。地域の移動では差を保つ。新規開始・つづきから・タイトルへ戻る操作で全場面を標準にする。会話・メニュー・一時停止・カットや専用カメラの間は上下入力を止め、保留中の分を捨てる。演出後は保持していた角度に戻る。

## 実装

`index.html` の `updateCamera()` で、既存の場面・戦闘状態から求めた距離と高さを基に回転する。差がゼロのときは既存の座標計算を使う。見上げの限界では軌道の半径を約 0.75 倍にして注視点を約 1 m 上げる。見下ろしの限界では注視点の前寄せを約 0.3 倍にする。屋内は天井がないため、見上げの限界を `CAM_PITCH.in.min` に置いた。天井を作った後にこの値を下げて範囲を広げられる。

カメラの遮りは既存の 3D 線分で調べる。屋内で上下に回したときは、補間後の位置も同じ線分で調べて手前の壁へのめり込みを抑える。目標位置の地面補正に加え、補間後の `cam.pos` も地面から 0.4 m 以上に保つ。横回転と横方向の自動追従には従来の処理を使う。

カーソル照準は従来どおり高さ 0 の平面を先に調べる。使える交点がないときは主人公の足元の高さを試し、それでも交点を使えない場合は自動照準、最後に主人公の向きに戻る。

設定は `localStorage` の `eiheiji_camPitch` に保存する。初期値と壊れた設定の代替値は `{v:1,sens:'std',inv:false}`。各場面の角度差はそのプレイ中の状態として扱う。

## 確認

`THREE_JS=ローカルのthree.min.jsへのパス node tests/cam-pitch-browser.cjs` で確認する。Playwright と Chromium が必要。標準構図と旧式の比較、PC とタッチ入力、角度の限界、場面の復帰、地面・屋内の壁、照準、演出、保存、ページエラーを確認する。必要に応じて `CHROMIUM_PATH` で Chromium の実行ファイルを指定できる。

`CAM_SHOTS=フォルダ` を指定すると、PC（1280×720）とスマホ（390×844）の標準・見上げ限界・見下ろし限界を、上志比の森・坂・建物の前、古い農家の中、運転中で撮影する。

初回の作業環境では Playwright と Chromium を起動できず、ブラウザテストと撮影は未実行だった。

`tests/story-f-touch-browser.py` の「初遭遇の会話」について、2026-11-26 に Claude Code が画面のない Chromium で最終テストを実行した。カメラの版（v0.90 候補の `c46be4e`）では通算13回中3回失敗し、main（`bdc2a1e`）では8回とも合格した。最終テストではカメラの版の1回目が失敗し、その後は負荷をそろえるため両版を同時に2回流し、両版とも2回とも合格した。失敗した3回はいずれも約417〜468秒かかったが、同じくらい遅い約450〜484秒の回でも合格している。記録つきの5回はすべて合格した。同じ条件で比べた24通りでは、標準の角度のカメラの位置とスズキの待避先は main と同じだった。**カメラの変更による回帰は確認されなかったが、カメラの版だけで失敗が出ている理由は特定できていない。** テストの待ち時間は実時間で計る。

## 2回目の修正

標準構図は固定コミット `bdc2a1e263502f2518129908e3edc77dc858ece3` の `updateCamera` と比較する。同じ状態から揺れを止めて各1コマを進め、目標位置・注視点・実際の位置が許容差 1e-6 以内で一致するかを、屋外・古い農家の屋内・運転中で調べる。旧版のファイルは `OLD_HTML` でも指定できる。C はキーイベントを送った直後に背後の向きと角度差 0 を確認する。

屋外で見下ろすときは、主人公の頭からカメラ候補までの線分と、庇の張り出しを含む屋根の箱を調べる。屋根に当たると目標の仰角を下げ、カメラは従来の補間で追従する。入力した角度差は保持し、屋根から離れるとその角度に戻る。標準の角度と農家の屋内にはこの補正を適用しない。
