- 2026-11-23。作業ブランチ `p3e2-felling-fix`（`p3e2-forest` の `cbdb745` から）。**commit・push・main への反映はしていない（ユーザーの承認待ち）。**
- きっかけ：ユーザーが iPhone の実機で、森林の試遊版の広葉樹に近づくと「杉を切る」と出て、切ると杉として扱われるのを確かめた（すべての広葉樹で起きるかは未確認）。

## 2. 根本の原因
1. **上志比の木の名前を、樹種ではなく大きさから付けていた。** 名前は表 `TSIZE`（細い木・杉・太い杉）の大きさの名前だけを使い、上志比の木の記録（`kamiTreeRec`）は大きさ（`mid`／`thick`）しか持たない。そのため広葉樹でも、案内が「杉を切る」「太い杉を切る」「杉：受け口を切る…」、倒したあとの丸太が「杉の丸太」「太い杉の丸太」と出ていた。実機で見た「杉を伐採する」はこれ。
2. **攻撃で切るとき、案内とは別のやり方で木を選び直していた。** 案内は「今の向き・1.6m」、攻撃は「攻撃の向き・1.3m」。直す前に 3,002 の立ち位置で数えると、604（約20%）は案内の木を切らない（空振り）、98（約3%）は別の木を切る（広葉樹のつもりで杉を切るものも含む）。「杉として処理された」と見えた原因の一つになりうる。

## 3. 直したこと（`index.html`。上志比だけ。光明寺の伐採は変えていない）

| 所 | 直したこと |
|---|---|
| `kamiTreeRec` | 記録に `name` を足す：広葉樹は「広葉樹」（大きい木は「太い広葉樹」）。杉は今までどおり（`name` なし → 「杉」「太い杉」） |
| `f4Interactables`（木） | 案内の名前を `rec.name`（無ければ今までの大きさの名前）に。案内に出ている木を `chop` として覚える |
| `f4Interactables`（上志比の丸太） | 広葉樹の丸太は「広葉樹の丸太」「太い広葉樹の丸太」。硬木になる丸太は「・山地の硬木+1」を出す |
| `f4Buck` | 上志比の広葉樹の丸太に印 `l[6]` を付ける（名前に使う。上志比の丸太は保存しないので、セーブは変わらない） |
| `f4ShownTarget`（新しい関数） | 上志比では、攻撃で木を切るとき、案内に出ている木（`curInter.chop`）を切る（届く範囲のとき） |
| `wantsChop`・`startAttack`・`f4AttachChop` | 攻撃で切る木を `f4ShownTarget()`（無ければ今までどおり `f4FindTarget(1.3)`）に |
| `f4FindTarget` | 見つけた木に当たり判定の半径 `r` を持たせる（案内の木がまだ届くか確かめるため） |

- 変えていないもの：木の分布と種類分け（`e2Classify`）・形・当たり判定・切る回数・倒れる向き・丸太の数・硬木の数・苗木・植林・成長・`kami.f`／`fb`／`pl` の形・光明寺の伐採・獣が近いときは木を切らない決まり・案内の文の形（名前のほかは同じ）。
- 変わる遊び方：上志比で、攻撃ボタンを押したとき、案内に出ている木（1.6m まで）を切る（今までは 1.3m より遠いと空振りだった）。
