## 4. 決めてほしいこと（ChatGPT・ユーザー）

**戦い方**
1. **蹴り3種**の名前・動き・威力・間合い・使い分け（どんなときにどれを出すか）。指示書 v3.0 の原文があれば、その部分を添えてほしい。
2. **臭いの継続ダメージ**：何が臭うのか（スズキの技か、体質か）、出る条件、範囲・1秒あたりの傷・続く時間。ボスに効かないのは原文どおりか。主人公・村人・慧心には効かないでよいか。
3. 背中の**棍棒**は戦いで使うか（飾りだけ／ある条件で振る）。
4. スズキから敵へ向かうか、主人公が狙った敵だけを攻めるか。

**体力と倒れたとき**
5. スズキの体力・守りの強さ。時間で回復するか、料理を食べるか。
6. **戦闘不能**：体力0で倒れて動かなくなる、でよいか。**助け起こし方**（近づいて E／行動ボタンを何秒長押し？）、起きたときの体力、放っておくとどうなるか（時間で自分で起きる／光明寺へ戻る／死なない）。
7. 主人公が倒れたとき、スズキはどうなるか（一緒に西の端で起きる？）。

**獣との関係**
8. どの獣がスズキを狙うか、どう選ぶか（近い方／最後に攻撃してきた方）。要塞の見張りはスズキも見つけるか。
9. 光明寺の襲撃（防衛戦）にスズキが加わるか。加わると防衛戦の勝ちやすさが変わる。

**ついて来る・残る**
10. ついて来るときの距離と速さ（陸上部なので主人公より速くてよいか）。離れすぎたときに近くへ移す距離。
11. 「上志比に残る」「ついて来い」の**指示の出し方**（話しかけて選ぶ？）と、残ったときの居場所（その場／山王）。
12. 光明寺での居場所と過ごし方（夜・襲撃のとき・拠点の仕事をするか）。

**そのほか**
13. 戦闘中の掛け声などの台詞を入れるか（入れるなら文面はユーザー・ChatGPT で。Claude は補作しない）。
14. 作業F より前に試せるよう、**試遊版だけ**にスズキを呼ぶボタンを付けてよいか（本編には作業F まで出さない）。

## 6. 既存の仕組みとの関係

| 作るもの | かかわる仕組み |
|---|---|
| ついて来る・引っかかり | `resolve`・上志比の家とバリケード（要塞の侵入経路は幅2m のものがある） |
| 蹴り・臭い | `damageEnemy`・ボスの判定（`e.type==='boss'`）・敵の怯み・ノックバック |
| 獣がスズキを狙う | 野の獣の AI（`f10Pre`・`f10Sees`）・要塞の見張り（`kfSees`）・変異したサル（`e.tgt`） |
| 倒れる・助け起こす | `interactables()`・`interact()`・主人公が倒れたときの処理（`docs/death-penalty.md`） |
| 地域の移動・残る | `regionTravel()`・`REG.live`・上志比を作るとき／捨てるとき |
| 防衛戦 | 光明寺の襲撃（`docs/p1-balance-report.md`）・勝率測定 `tools/defense-sim.cjs` |
| セーブ | 新しいキー（例：`suzuki`）。保存キー・`v:1`・既存キーは変えない。古いセーブは「まだ仲間でない」で始める |

## 7. 想定される技術的な問題

1. **引っかかり**：上志比は家・田・バリケードが多い。一定時間動けなければ主人公の後ろへ移す（作業環境では未検証）。
2. **獣の狙いの切り替え**：今の獣の AI は主人公だけを見ている。スズキを狙えるようにすると、光明寺の獣・防衛戦の動きにも触れるので、勝率測定で変化を確かめる必要がある。
3. **地域の移動**：上志比は入るたびに作り直す。スズキを地域ごとに作り直すと、体力・倒れているかを持ち越す仕組みが要る。
4. **iPhone の重さ**：人が1人増えるだけなので小さいと見込むが、実機の確認はユーザーにお願いする。
5. **作業F との順番**：初遭遇のカットではスズキが変異したサルに追われる。仲間 AI ができていれば、そのまま使える。

## 8. 推奨する開発順序
