# P3-E の E-2 丸太の種類を保つ修正

基準は p3e2-felling-fix の f0abc54dd9acfa69f1dc79d2c4982eb9c24e58f7。実装ブランチは p3e2-truck-log-attrs。本編 v0.88 が対象。

## 原因と設計

伐採・枝払いでは、太さ、割ると硬木になる印、広葉樹の印をそれぞれ持つ。荷台、担ぎ、一輪車は太さの記号だけを受け取っていたため、荷下ろし時に印が消えていた。

- 印は 0（なし）、1（割ると山地の硬木）、2（広葉樹）、3（両方）。地面の丸太は従来の l[5] と l[6] を使う。
- 実行中の荷台の印は、丸太の配列をキーとした WeakMap に置く。荷台の積む・下ろす・空にする処理をまとめ、太さと印を同時に動かす。保存では最上位の logAttr.bed に印と太さの並びを記録する。
- 光明寺の地面の丸太は f4.logA、担いだ丸太は f4.carryA、一輪車の丸太は f4.cart.logA に印を保存する。既存の丸太・担ぎ・一輪車の記録の形は従来どおり。上志比の地面の丸太は地域を出ると消える。
- 読み込みでは保存された丸太と印を組にしてから不正な丸太を除き、上限を適用する。欠けた配列や長さの異なる配列の印は全て0。不正な印は個別に0。荷台は保存した太さの並びとも照合する。

## 決定 D1〜D6

| 決定 | 実装 |
|---|---|
| D1 | 光明寺でも硬木の印を持つ丸太を割ると山地の硬木+1。上志比と同じ通知で、太さごとの木材は従来どおり。 |
| D2 | 荷台・担ぎ・一輪車から置き場に納入した丸太と、源さんが運んだ丸太は太さに応じた木材だけになる。 |
| D3 | 担ぐ・一輪車・荷台への積み下ろしで印を引き継ぐ。丸太を積んだ一輪車を押していると、置く操作から1本下ろす選択肢を開ける。置き場での納入と近くの丸太の積み込みは引き続き優先される。 |
| D4 | 光明寺の案内に「広葉樹の丸太」「太い広葉樹の丸太」と、割ったときの「山地の硬木+1」を印に応じて表示。 |
| D5 | C-4 の林道の丸太も対象の輸送経路を通る。main 側への反映は E-2 の正式採用時。 |
| D6 | **別の優先課題**。源さんが丸太を1本手に持っている途中に保存すると、その1本が消える既存の挙動。今回は運搬中の保存形式を変更しない。 |

## セーブ互換性

本編の保存キー eiheiji_vs_beasts_v010 と形式 v:1 を維持する。例は次のとおり。

    修正前  truck.bed = {"logs":["m","k","m"],"mats":{},"foods":{}}
    修正後  truck.bed = {"logs":["m","k","m"],"mats":{},"foods":{}}
            保存データ最上位 logAttr = {"v":1,"bed":{"a":[0,0,3],"s":"mkm"}}
            f4 = {"logs":[[12,7,0,"m"]],"logA":[3],"carry":"t","carryA":2,
                  "cart":{"x":12,"z":8,"a":0,"logs":["k"],"logA":[3]}}

- 旧セーブ → 新版。印が無ければ0。丸太の本数、太さ、順番と木材の量は従来どおり。すでに失われた印は復元しない。
- 新セーブ → 旧版。同じ保存キーを使う版は丸太の太さを読み取れる。未保存のまま新版に戻れば印は残る。
- 旧版の保存処理は最上位の logAttr と f4 の logA・carryA・cart.logA を書かない。旧版で一度保存し直すと、丸太に触れていなくても全ての印が失われ、元に戻せない。同じ太さの丸太を入れ替えた場合でも、新版で別の丸太に印が付くことはない。
- 同じ太さの丸太を旧版で入れ替えたかどうかは判定できない。手編集したセーブは保証の対象外。荷台の署名で検知できるのは太さの並びの不一致まで。

## コードレビュー用の確認箇所

| 対象 | 書き込み経路 |
|---|---|
| 荷台 | bedLogPush・bedLogPop・bedLogClear のみ。trkSys は太さと印を組にして補正してからクリアと追加を行う。bedAddLog、bedTakeGroundLog、bedDropLog、bedLoadCarry、bedDeliverLogs、haulUpdate は同じ経路を通る。 |
| 担ぎ | f4CarrySet で太さと印を同時に設定。f4PickLog、f4DropLog、f4Deliver、bedLoadCarry、f4Load から呼ぶ。f4Fresh は両方0で初期化する。 |
| 一輪車 | cartLogPush、cartLogTake、cartLogClear のみ。f4Interactables、f4Deliver、f4Load が使う。f4Load、f4Apply、作業台の一輪車レシピは空の初期値を両方用意する。 |
| 地面 | f4Buck が伐採時の印を付ける。f4ClearClosure の倒木に印は無い。f4DropLog、一輪車の荷下ろし、bedDropLog、f4Load は logAttrSet で印を付けてから配置する。積み込み・担ぎで取り出すときは logAttr で印を読む。割る処理と上志比の本数上限は丸太ごと除く。 |
| セーブ | saveGame は bedLogSave で最上位の logAttr を書く。applySave は車両の荷台上限を復元してから trkSys で読む。f4Save・f4Load は光明寺、担ぎ、一輪車の印を読み書きする。 |

## テスト

- 新規の node tests/p3e2-truck-logs.cjs は、上志比・光明寺での積み下ろし、再積載、J で割る、担ぎ、一輪車、納入、積載上限、旧版との同一オリジンでの保存往復を検証する。THREE_JS に Three.js r128 を設定する。既定の旧版は origin/main の本編。OLD_HTML で差し替えられる。
- TRUCK_PAGE を使う場合は試遊版の保存キーを検証し、OLD_PAGE で旧試遊版を指定できる。試遊版自体への修正の反映とその検証は統合時に行う。
- 本編の新規 Playwright テストは 1〜9d が PASS。既存の Node.js テスト6本も PASS。
