## 1. 今回の開発目標

- 防衛戦を「準備なし／一部準備／十分な準備」の3条件で検証する。
- **解放済みの装備・防衛設備を十分に準備しなければ、ほぼ勝てない**。十分に準備すれば、公平で納得感をもって勝てる。
- 「全アイテム・全施設の100％完成」を必須にはしない。
- 調整した値は「暫定」として記録する。

## 3. 過去の確定仕様（引き継ぎ仕様書 Handoff v2.0 より）

- 侵入は三方向。敵は猿・猪・熊の混成。
- 準備不足なら難しく、十分な準備に報いる難易度。準備不足でも偶然簡単に勝てる状態にも、準備しても理不尽に詰む状態にも戻さない。
- 敗北後に再挑戦でき、クリア済みでも再挑戦できる。クリア記録は失わない。
- 源さんは警告と再挑戦の窓口、慧心は柵の修理を担う。
- 何の準備が足りないのかを、プレイヤーが学べる情報設計にする。
- 波の間に、補修や罠の掛け直しが実際にできること。
- スマホでも三方向の変化が分かり、操作の不具合がないこと。
- 再挑戦の後も、セーブ・報酬・章フラグが二重になったり消えたりしないこと。

**注意：** 過去の報告にある「3波、敵総数18→30、敵HP×2、攻撃×1.6、波間18秒」は今のコードと一致しています。ただし、これがユーザーの確定値なのか、開発上の暫定値なのかは分かりません（`docs/chapter2-progress.md` には「試作用の調整値」とある）。

## 5. 新しく必要な3Dモデル

- **なし。** 既存の猿・猪・熊・火の見やぐら・柵・罠で足ります。
- 「猿の統率者」を戦場に登場させる場合だけ、新しいモデルが必要です。その場合は、仮モデル（既存の猿の拡大や色違い）で先に作れます。

## 6. 既存システムとの依存関係

| システム | 関係 |
|---|---|
| 武器表 `WEAPONS` | 鉈Lv1：軽攻撃10・強攻撃26。牙槍：22・58。鉄の斧：16・44 など。準備の差は主にここで出る |
| 防具 `G47`（頭・胸・脚・靴） | 被ダメージを部位ごとに軽減する。プレイヤーの体を戻したため、見た目は頭だけ表示 |
| 柵 `GAPS`・罠・杭柵・落とし穴・餌場 | 猪・熊を止める。猿は柵を越えてやぐらを狙う |
| 慧心の修理・源さんの案内 | 支援の量が難易度に直接効く |
| 育成（レベル・最大HP・熟練） | 「十分な準備」にレベルを含めるかで結果が変わる |
| 回復食（おにぎり・弁当・焼き野菜・薬草粥） | 戦闘中の立て直し |
| 倍率 `f11InvHp`・`f11InvDmg` | 第1章の大規模侵攻と共用の関数。第2章だけに効くよう分岐している |
| セーブ | 戦闘中の保存は準備状態に戻る。`defenseComplete` を失わない |

## 7. 想定される技術的問題

1. **勝率を測る道具がない。** 3条件を比べるには、自動で戦うボットと、画面を描かずに速く回す仕組みが要ります。画面つきの確認（SwiftShader）は1回に数分かかり、回数を重ねられません。
2. **ボットの勝率は、人の勝率と同じではない。** ボットの結果は目安にとどめ、最終的にはユーザーの試遊で確かめる必要があります。
3. **乱数があるため、1条件につき数十回は回す必要がある。**
4. **第1章を変えないこと。** 倍率の関数を共用しているため、変更のたびに第1章の数値が変わっていないかをテストで確かめます。
5. **iPhone での負荷。** 敵8匹が同時に出たときの FPS は未確認です。
6. **プレイヤーの体を戻した影響。** 攻撃の当たり方や見た目の距離感が、防衛戦の調整時と変わっていないかを確かめます。

## 8. 推奨する開発順序

1. 3条件の定義と目標勝率を決める（ユーザーと ChatGPT）。
2. 勝率を測る道具を作る：作業ブランチで、ボットと高速シミュレーションを作る。ゲーム本体の動きは変えない。
3. 今の値のまま、3条件の勝率を測る（基準値）。
4. 目標とのずれを見て、調整案を出す。値は「暫定」と明記し、承認を得る。
5. 調整を入れ、第1章が変わっていないことと、セーブ・記録・再挑戦をテストで確かめる。
6. ユーザーが PC と iPhone で試遊し、結果を受けて再調整する。
7. 確定した値と測定結果を `docs/` に記録し、main に反映する。
