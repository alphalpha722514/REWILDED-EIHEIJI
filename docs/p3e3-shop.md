# E3-3a よろず屋の実装を引き継ぐ

v0.91 の house110 に、中央通路のある仮の売場と、店主の住まいにあたる2階がある。拠点設立後、古い農家の蔵の棚で地図を手に入れ、よろず屋の正面で E または行動ボタンを押す。地図を持っていないと「ここから入る手がかりがない」と表示する。通常退出では入店時の店先へ、「つづきから」では上志比の屋外到着点へ戻る。

## 保存とゲームの再開

`saveGame` 9349 は共通の `chapter2` をそのまま書く。保存キーは `eiheiji_vs_beasts_v010`、版は数値の `1`。店内で第2章を保存したときも `chapter2.currentChapter` は数値の `2`、`currentRegion` は `kamishihi` になる。階・暗転・入力の状態は実行時だけに持つ。`continueGame` 9456 と `regionTravel` 10295 が地域の `arrival` に主人公を置く。

| 保存時のスズキ | 読み込み時 |
|---|---|
| 健在で追従中 | `szApplyLoad` 13997 と `szPlaceTick` 14003 が主人公の近くに置く。 |
| 店内のどちらかの階で待機・転倒 | `szSave` 13979 が店先の空き点を既存の `suzuki.x/z` と `wx/wz` に書く。保存中のゲーム内座標は維持する。転倒者は体力0のまま店先で救助できる。 |
| 保存時に店先の候補がすべて埋まっている | 元の店内座標と待機目標を保存する。`szAfterTravel` 13973 が屋外の当たり生成後に店の矩形を識別して店先を再検査し、必要なら既存の後方配置を使う。 |
| 既に屋外で待機中 | 保存した元の位置と待機目標を復元する。 |

## 試験の流し方

作業フォルダの直下で実行する。

```sh
tail -c 14 index.html
node tests/chapter2-save.cjs
python3 -m py_compile tests/p3e3-shop-browser.py
```

末尾14バイトは `</body></html>`。Node 試験はインラインスクリプトを構文解析する。さらに、スズキ未加入で他の状態を固定し、屋外・店の両階で保存した生の JSON の全項目を照合する。砂場ではこれらに合格した。Node の模擬試験でも階別の当たり・別階待機・転倒退出・店先全閉塞時の引き継ぎ・移動と明転の例外後の復帰を確認した。

ブラウザー試験には Python Playwright の時計 API（1.45以降）、対応する Chromium、ローカルの Three.js r128 を使う。`THREE_JS` は既存の `three.min.js` のパスで、Chromium の保管場所を指定する環境では `PLAYWRIGHT_BROWSERS_PATH` も設定する。次のコマンドは本編と素材をローカルからブラウザーへ渡す。

```sh
export THREE_JS=/手元のパス/three.min.js
python3 tests/p3e3-shop-browser.py
python3 tests/p3e3-farm-browser.py
```

よろず屋試験は PC 1280×720 と iPhone 寸法 390×844 で実行する。`boundary`（試験139行）は本物の明転が終わって面を外す直前に同期し、短い入力列の間だけ時計を止める。次の階段・出口・入口の案内を有効にした状態で、キーのリピートと新規押下、または座標タップを送り、受信先と遷移回数を検査する。タップの受信先は解除前が暗転面、解除後が行動ボタン。引き続く意図的な入力で次の遷移が成立することまで確かめる。

`raw_save`（試験210行）は `localStorage` の値を直接検査する。店を出た後の地図の描画、農家入口での同行指示との競合、上下の視角での上壁、農家・本部・整備工場跡の往復も同じセッションで調べる。E3-2 の旧版往復まで再検査する場合は、手元の v0.90 本編を明示して `OLD_HTML=/手元のパス/v0.90/index.html python3 tests/p3e3-search-browser.py` を実行する。砂場には Python Playwright がなく、ブラウザーでの結果は次の環境で確認する。
