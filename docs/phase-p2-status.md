- セーブは今の形式（`v:1`・既存キー）のまま、どちらの地域にいるかを保存する。旧セーブは光明寺から始まる。
- **P2 に入れないもの（案）：** 軽トラック・上志比の拠点施設・復興（P3）、双子猿と廃工場（P4）。

## 6. 既存システムとの依存関係

ほとんどのシステムが「世界は光明寺ひとつ」を前提にしています。上志比を足すには、これらを地域ごとに分ける必要があります。

| システム | 今の作り | 地域分けで必要なこと |
|---|---|---|
| 地図データ `MAPDATA`・`BOUNDS` | 光明寺だけ。起動時に読み込む | 地域ごとのデータと範囲 |
| 地形・道・建物の生成 `buildWorld()` | 起動時に一度だけ作る | 地域ごとに作って捨てる（メモリを返す） |
| 当たり判定 `circles`・`gridQuery` | 光明寺の木・建物・柵 | 地域ごとに作り直す |
| 拠点・柵・やぐら（`BX`・`BZ`・`GAPS`・`CORE`） | 光明寺の拠点に固定 | 光明寺にいるときだけ有効にする |
| 採集場所 `NODES`・獣の出現 `SPAWNERS` | 光明寺の位置 | 地域ごとの一覧 |
| 村人 `NPCS`（源さん・区長など） | 光明寺に配置 | 地域ごとの表示 |
| 伐採 `f4`・畑 `f8`・探索 `f5` のセーブ | 光明寺の木や岩の番号で保存 | 光明寺の記録はそのまま。上志比の分は別に持つ |
| 全体地図・ミニマップ `drawMap` | 光明寺の地図を描く | 地域ごとに描く |
| 襲撃・防衛戦 `ev` | 光明寺の拠点が舞台 | 上志比にいる間は起こさない（または扱いを決める） |
| セーブ `chapter2.currentRegion` | 常に `komyoji` に戻す | 上志比に入れるようになったら、保存した地域を復元する |

## 7. 想定される技術的問題

1. **1つの世界前提の作りを分けるのが一番大きい作業。** 先に「光明寺の動きを一切変えずに、地域単位の作りに置き換える」段階を挟み、テストと防衛戦シミュレーターで変化がないことを確かめてから上志比を足すのが安全です。
2. **地図データを作る道具がリポジトリにない。** 光明寺の `MAPDATA` を作った処理は残っていません。上志比用に作り直します。この作業環境から確かめた結果：国土地理院の標高タイルは取得できた。OpenStreetMap の道路・建物を取得する窓口（Overpass）にはつながらなかった。道路と建物は国土地理院のベクトルタイルから取るか、ユーザーに OSM の抜き出しファイルを用意してもらう必要があるかもしれない（未確認）。
3. **ファイルの大きさと iPhone の負荷。** 上志比を同じ1ファイルに入れると約9MB以上になります。地域のデータを別ファイルにして必要なときだけ読む方が軽くなりますが、今の「1ファイル」の形から変わります。どちらにするか決める必要があります。
4. **メモリ。** 2つの地域を同時に持たず、切り替えのときに前の地域を確実に捨てる必要があります。iPhone で何度往復しても落ちないかを確かめます。
5. **セーブ互換。** `SAVE_KEY`・`v:1`・既存キーは変えません。上志比の記録は `chapter2` の中か新しいキーに入れ、旧セーブは光明寺から始めます。
6. **出典の表示。** 光明寺と同じく、国土地理院・OpenStreetMap・e-Stat などの出典をタイトル画面に表示します。

## 8. 推奨する開発順序

1. P2 の範囲と、上の「4. 不明な仕様」を決める（ユーザーと ChatGPT）。
2. 地図データを作る道具をリポジトリに入れる。上志比の標高・道路・建物・川を取得し、出典・取得日と一緒に保存する。
3. 光明寺を「地域」として扱う作りに置き換える。**ゲームの動きは変えない**（全テストと防衛戦シミュレーターで確認）。
4. 上志比の地形・道・家並み・田畑・川を作り、歩いて探索できるようにする（獣・採集は決まった範囲で）。全体地図とミニマップも地域に合わせる。
5. 境目のロードと往復の移動、どちらの地域にいるかの保存を入れる。旧セーブの読み込みを確かめる。
6. 出発のきっかけ・目的欄・台詞を入れる（決まった台詞だけ）。
7. PC と iPhone で試遊し、表示・速さ・往復で落ちないかを確かめる。
8. 記録を `docs/` に残し、main に入れる。軽トラックと拠点施設は P3。
